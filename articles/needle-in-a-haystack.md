# Needle in a Haystack (NIAH)

> 긴 문서 속 **어딘가에 숨긴 사실 한 줄(needle)을 모델이 찾아 답하는지** 보는 장문 검색 시험이다. 점수가 좋아도 긴 입력 전반의 능력을 보증하지는 않는다.

## 쉽게 말하면
두꺼운 책 한가운데에 "비밀번호는 7391"이라는 쪽지를 끼워 놓고 "비밀번호가 뭐였지?"라고 묻는 시험이다. 쪽지 찾기는 잘해도 책 전체를 이해하고 종합하는 건 별개다.

## 자세히
(Greg Kamradt의 GitHub 저장소와 Chroma의 "Context Rot" 연구 글을 직접 읽었다.)
- **방식(저장소)**: 컨텍스트 길이와 **needle 삽입 깊이**를 조합해 훑는다. 각 칸마다 needle(사실)을 haystack 문서의 정해진 깊이에 넣고, 질문을 던져 응답을 채점한다. 기본 haystack은 Paul Graham 에세이. 과제 유형: 단일 사실, 다중 사실, UUID 하나 찾기, UUID 연쇄(다단계 추론). 라이선스 MIT(원저자 표기 요구).
- **원래 시험(저장소)**: 2023-11-08 OpenAI GPT-4 128K, 2023-11-21 Anthropic Claude 2.1 실행이 인용된다(결과는 차트 링크로만 연결, 본문 요약 없음).
- **한계(Chroma)**: NIAH는 "근본적으로 단순한 검색 과제"로 **어휘 일치**를 주로 시험해, 만점에 가까워도 균일한 장문 능력을 의미하지 않는다. 어려운 변형 NoLiMa는 어휘 겹침이 없는 쌍을 쓰며 쌍의 **72.4%**는 외부 세계 지식이 필요하다.
- **Chroma 실험(18개 모델)**: needle-질문 유사도가 낮을수록 길이 증가에 따라 더 빨리 성능 저하(유사도 0.445~0.775/0.521~0.829). **방해 요소(distractor)** 하나로 성능이 떨어지고 4개면 더 악화 — GPT는 환각이 가장 많고 Claude는 답을 보류하는 경향. haystack을 문장 섞기로 만들면 일관된 에세이보다 **오히려 성능이 높았다**(18개 전 모델). LongMemEval 306개 프롬프트에서 집중 입력(약 300토큰) vs 전체(약 11.3만 토큰)는 크게 차이. 반복 단어 과제에서 모든 계열이 길이에 따라 저하.
- **결론(Chroma)**: "입력이 길어질수록 성능이 점점 불안정해진다", 단순한 과제에서도.
- **한계 주의**: Chroma는 Chroma 사의 연구이며 이해관계가 있는 벤더 연구다(해석).

## 예시
- 사내 문서 20만 토큰을 한 번에 넣는 챗봇을 만들 때 NIAH 만점을 근거로 삼지 말고, 실제 질문(여러 문단 종합)으로 시험한다(제안).

|---|---|
| NIAH | 숨은 사실 하나 찾기(어휘 일치 중심) |
| NoLiMa | 어휘 겹침 없는 검색 |
