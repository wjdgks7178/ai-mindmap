# 배포와 호스팅

> 로컬에서 만든 앱을 서버에 올려 인터넷 주소로 남이 쓰게 만드는 일(배포)과, 그 앱이 올라가 있는 공간(호스팅).

## 쉽게 말하면
집에서 만든 요리를 가게를 빌려 메뉴로 내놓는 일이다. 가게 임대(호스팅), 간판과 주소(도메인), 오픈 준비(배포)가 필요하다.

## 자세히
Vercel 문서(2026-09 갱신본) 기준 개념:
- **배포(deployment)** = 프로젝트를 성공적으로 빌드한 결과물. 배포마다 고유 URL이 생긴다.
- 만드는 법: ① **Git 연결**(푸시하면 자동 배포, 가장 흔함), ② CLI(`vercel deploy`), ③ 폴더 드래그, ④ 배포 훅 URL, ⑤ REST API.
- **환경**: Local(내 PC) → Preview(PR마다 시험용 URL) → Production(실사용 주소). Preview에서 확인 후 `--prod`로 올린다.
- **롤백**: 문제가 생기면 이전 배포로 되돌릴 수 있어야 한다.
- 정적 사이트(GitHub Pages 등)는 서버 코드가 없어 쉽고 싸다. 백엔드·DB가 필요하면 서버리스 함수나 컨테이너 호스팅을 쓴다.
- 체크리스트: 환경 변수 등록([비밀 관리](#secrets-env)), 도메인·HTTPS, 로그 확인, 비용 상한 설정.

## 예시
- GitHub 저장소를 호스팅 서비스에 연결 → main에 푸시하면 자동 배포.
- 이 개념 지도 사이트도 GitHub Pages(정적 호스팅)로 공개한다.

## 헷갈리는 것과 비교
| 개념 | 차이 |
| --- | --- |
| 배포 | 결과물을 올리는 행위 |
| 호스팅 | 올려진 앱이 실행되는 공간 |
| 도메인 | 사람이 읽는 주소. 호스팅과 따로 구입 |
| CI/CD | 테스트와 배포를 자동화하는 파이프라인 |
