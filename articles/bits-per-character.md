# BPC(문자당 비트)

> BPC(Bits Per Character)는 언어 모델이 글자 하나를 예측하는 데 평균 몇 비트가 드는지 나타낸다. 토큰 단위인 PPL과 달리 토크나이저가 달라도 비교하기 쉽다.

## 쉽게 말하면
같은 편지를 압축 프로그램 두 개로 압축해 용량을 비교한다고 생각하자. 사전 크기나 쪼개는 방식이 달라도 "최종 파일이 몇 비트냐"는 공정한 비교가 된다. BPC는 모델을 압축기로 보고, 글자 하나당 평균 몇 비트로 표현하는지 재는 것이다. 낮을수록 글을 잘 예측한다.

## 자세히
- Hugging Face 문서는 PPL이 BPC 및 데이터 압축과 관련 있다고 안내한다. PPL은 교차 엔트로피의 지수이고, 교차 엔트로피를 밑 2 로그로 재면 비트 단위 값이 된다.
- 환산(수학적 관계): `BPC = (토큰 수 / 문자 수) × log₂(PPL)`. 토큰당 손실을 문자당 손실로 바꾸는 것이므로, 같은 말뭉치에서 문자 수는 고정이고 토큰 수만 토크나이저마다 다르다.
- 모델 둘을 BPC로 비교하면 토큰이 크든 작든 총 정보량 기준으로 맞춰 볼 수 있다. 문자 인코딩 차이(한글 3바이트 등)까지 지우려면 [바이트당 비트](#bits-per-byte)를 쓴다.
- 한계: 같은 말뭉치·같은 전처리를 써야 한다. 한국어처럼 글자 수당 정보량이 다른 언어끼리는 비교가 어렵다.

## 그림으로 보기
```mermaid
flowchart LR
  P["토큰 PPL"] --> L["log2 → 토큰당 비트"]
  L --> M["× 토큰 수 = 총 비트"]
  M --> D["÷ 문자 수"]
  D --> B["BPC"]
```

## 예시
- 같은 위키 텍스트 1만 자에서 모델 A는 3,000토큰·PPL 20, 모델 B는 2,000토큰·PPL 40. A: 0.3×log₂20≈1.30, B: 0.2×log₂40≈1.06 → B가 글자당 비트가 낮아 더 좋다. PPL만 보면 A가 좋아 보이는 역전이다.

## 헷갈리는 것과 비교
| 개념 | 차이 |
| --- | --- |
| [PPL](#perplexity) | 토큰당, 토크나이저 의존([설명](#perplexity-tokenizer-dependence)) |
| BPC | 문자당 비트 |
| BPB | 바이트당 비트, 인코딩 영향까지 제거 |
