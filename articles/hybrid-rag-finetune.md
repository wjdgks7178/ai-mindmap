# RAG+파인튜닝 조합

> 말투·형식·추론 방식은 파인튜닝으로, 최신·대량 사실은 RAG로 나눠 맡기는 하이브리드 설계. RAFT가 대표 레시피다.

## 쉽게 말하면
직원 교육(파인튜닝)으로 업무 방식과 어투를 몸에 익히고, 일할 때는 사내 위키(RAG)를 펴 놓고 최신 정보를 찾아 쓰게 하는 것이다. 교육만 받고 위키가 없으면 낡은 지식으로 일하고, 위키만 있고 교육이 없으면 자료를 읽는 법이 서툴다.

## 자세히
- **역할 분담**: 변하는 사실·출처 인용 → RAG, 일관된 형식·도메인 용어·절차 → 파인튜닝([문서 붙여넣기 진단](#context-paste-test)으로 어느 쪽 문제인지 먼저 확인).
- **RAFT(Retrieval Augmented FineTuning, arXiv 2403.10131)**: 질문+검색 문서(관련 문서와 방해용 distractor 섞음)를 주고, 관련 문장을 그대로 인용하는 사고 과정형 답으로 학습한다. 방해 문서를 무시하는 법을 배운다. PubMed·HotpotQA·Gorilla에서 도메인 RAG 성능이 일관되게 개선된다고 초록에 쓰여 있다(구체 수치는 초록에 없음).
- **농업 사례 연구(arXiv 2401.08406)**: Llama2-13B·GPT-3.5·GPT-4로 실험. 파인튜닝으로 정확도 +6%p 이상, 그 위에 RAG가 약 +5%p를 더해 효과가 누적됐다고 보고(한 지역 데이터 한정 사례).
- **비용·운영**: 인프라가 둘이므로 복잡도가 오른다. 단일 방식이 평가 기준을 넘으면 하이브리드를 하지 않는다.
- 대안: 긴 컨텍스트로 현재 문서 + RAG로 나머지.

## 예시
- 법률 요약 서비스: 판례 DB는 RAG(매주 갱신), 요약 문체·섹션 구조는 파인튜닝으로 고정.
- 학습 데이터 구성(RAFT식): 질문 1개 + 정답 문서 1 + 방해 문서 3, 일부 샘플은 정답 문서 없이 구성.

## 헷갈리는 것과 비교
| 개념 | 차이 |
|---|---|
| RAG만 | 지식은 최신, 형식 불안정 가능 |
| 파인튜닝만 | 형식 안정, 지식 낡음 |
| 하이브리드 | 둘 다, 비용·복잡도↑ |
| [RAG](#rag) | 검색 주입 |
