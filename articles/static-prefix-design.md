# 정적 앞부분 설계

> 프롬프트 캐싱이 잘 맞도록 **바뀌지 않는 내용을 앞에, 자주 바뀌는 내용을 뒤에** 배치하는 설계다.

## 쉽게 말하면
책의 목차와 서문은 그대로 두고 본문 끝 몇 쪽만 새로 써야 한다면, 앞부분을 다시 인쇄할 필요가 없다. 프롬프트도 앞부분이 매번 같아야 재사용된다.

## 자세히
(Anthropic 프롬프트 캐싱 문서를 앞부분 약 10만 자까지 직접 읽었다. 나머지 약 5.5만 자는 읽지 못했다. 수치는 문서 확인 시점의 값이며 모델·날짜에 따라 바뀐다.)
- **접두사 순서(문서)**: `tools` → `system` → `messages`. 앞 단계가 바뀌면 이후 전부 **무효화**된다. 그래서 정적 내용을 먼저 둔다.
- **브레이크포인트(문서)**: 자동(`"cache_control": {"type":"ephemeral"}`를 최상위에, 대화가 늘면 마지막 캐시 가능 블록으로 이동; Bedrock 미지원) 또는 블록별 명시(최대 4개). **매 요청 그대로인 마지막 블록**에 둔다. 타임스탬프처럼 매번 바뀌는 블록에 두면 **매번 캐시 쓰기만 내고 읽기는 못 한다**.
- **흔한 무효화 요인(문서)**: 도구 정의, 시스템 프롬프트, `tool_choice`, 프롬프트 어디의 이미지, thinking 설정, `output_config.effort` 변경.
- **TTL(문서)**: 기본 5분(읽을 때마다 무료로 갱신, 응답 생성 시간도 소모), `"ttl":"1h"` 선택 시 쓰기 단가 더 높음. 섞어 쓸 때 1시간 항목이 5분 항목보다 앞.
- **최소 길이(문서 예)**: 모델마다 다름(512, 1,024, 4,096 토큰 등). 미만이면 에러 없이 캐시 없이 처리된다.

```mermaid
  T["도구 정의 (고정)"] --> S["시스템 프롬프트·참고 문서 (고정) ◀ 브레이크포인트"]
  S --> M["대화·질문 (가변)"]
```

## 예시
```json
"system": [
  {"type":"text","text":"...고정 지침..."},
  {"type":"text","text":"...긴 참고 문서...","cache_control":{"type":"ephemeral"}}
]
```
- 현재 날짜·사용자 이름 같은 가변 정보는 캐시 블록 뒤에 둔다(제안).
