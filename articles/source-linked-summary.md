# 원문 링크형 요약

> 요약의 **각 문장에 근거가 된 원문 구간(전사의 몇 번째 발화, 어느 페이지)을 연결**해 두는 방식. 읽는 사람이 클릭 한 번으로 원문을 확인할 수 있어 오류 검수 시간이 줄고 신뢰가 높아진다.

## 쉽게 말하면
논문의 각주와 같다. 요약에 "고객이 환불을 요청했다[12]"라고 쓰고 [12]를 누르면 통화 전사의 해당 발화로 바로 간다. 믿어도 되는지 직접 확인할 수 있다.

## 자세히
출처: Claude API Citations 공식 문서(platform.claude.com, 본문 저장본 확인, 2026-11-18). 다른 모델·플랫폼의 유사 기능은 확인하지 못했다.
- **개념**: 모델이 문서에 근거해 답할 때 주장마다 인용(citation)을 붙이도록 하는 기능. 응답에 여러 텍스트 블록이 생기고 각 블록에 주장과 그 근거 인용 목록이 담긴다.
- **켜는 법**: 문서(PDF, 일반 텍스트, 커스텀 콘텐츠)마다 `citations.enabled=true`. 한 요청에서 전부 켜거나 전부 끄는 방식이다. 이미지 인용은 미지원, 텍스트만.
- **인용 형식 세 가지**: 일반 텍스트는 문자 인덱스(`char_location`, 0부터, 끝 제외), PDF는 페이지(`page_location`, 1부터), 커스텀 콘텐츠는 블록 인덱스(`content_block_location`, 0부터).
- **통화 전사에 적합한 형태**: 문서 설명은 목록·전사·세밀한 인용에 커스텀 콘텐츠를 권한다. 발화 한 줄을 블록 하나로 넣으면 "요약 문장 → 발화 번호" 연결이 된다(문서의 권고에서 이어지는 적용이며 문서가 통화 요약 예를 든 것은 아니다).
- **장점(문서 서술)**: 인용된 원문 `cited_text`는 출력 토큰으로 세지 않는다. 파싱된 포인터라 제공 문서에 대한 유효한 위치임이 보장된다. Anthropic 평가에서 프롬프트로 인용하게 하는 것보다 관련 인용 선택이 의미 있게 낫다고 한다(제조사 주장).
- **주의**: 입력 토큰이 약간 늘어난다. **구조화 출력(strict JSON 스키마)과는 함께 쓸 수 없다**(인용 블록을 텍스트와 교차 배치하기 때문). 인용이 "있다"는 것이 주장이 "옳다"는 보증은 아니므로, 인용 구간이 실제로 문장을 뒷받침하는지 샘플 검수가 필요하다(해석).
- **STT 오류와의 관계**: 링크는 전사에 연결되므로 전사 자체가 틀렸다면 원문 확인도 틀린 근거를 가리킨다. 중요 건은 음성 구간 링크까지 둔다([숫자·고유명사 오인식](#number-entity-errors)).

## 예시
```python
doc = {"type": "document",
       "source": {"type": "content", "content": [{"type": "text", "text": t} for t in utterances]},
       "title": "통화 전사", "citations": {"enabled": True}}
# 응답의 citation: {"type": "content_block_location", "start_block_index": 11, "end_block_index": 13}
```
교육 활용: 컨택센터 직무 교육에서 "AI 요약을 검수할 때 근거 링크가 있으면 얼마나 빨라지는가"를 비교 실습.
