# AI 보조 개발

> 코드를 AI에게 맡기되 사람이 목표를 정하고 결과를 **검토·테스트**하며 책임지는 전문 개발 방식.

## 쉽게 말하면
유능하지만 이 회사 사정을 모르는 신입 개발자에게 일을 시키는 것과 같다. 배경을 알려 주고, 끝났다는 기준을 주고, 결과물을 직접 확인해야 한다. 믿고 승인만 누르면 사고가 난다.

## 자세히
Claude Code 문서의 핵심 조언(2026-10 확인):
- **AI가 볼 수 없는 것을 알려 준다**: 배포 절차, 읽으면 안 되는 파일, 프로젝트 규칙은 코드만으로 알 수 없다. 반복되는 지식은 `CLAUDE.md` 같은 지침 파일에 적는다([AGENTS.md](#agents-md)).
- **확인할 수단을 준다**: 테스트·빌드·린트 명령을 알려 주고 통과해야 "끝"으로 친다([에이전트 검증 루프](#agent-verification)).
- **규칙은 강제한다**: 예외 없는 규칙은 문장 부탁이 아니라 훅·권한 설정으로 막는다.
- 흐름: 탐색 → 계획 → 구현 → 검증 → 커밋. 큰 변경은 계획부터 사람이 승인한다.
- 사람이 하는 일: 요구 정의, 설계 판단, 코드 리뷰(특히 보안·데이터 처리), 배포 결정.
- 바이브코딩과의 차이: [바이브코딩](#vibecoding)은 결과 화면만 보고 가는 탐색적 방식이고, 이 방식은 코드 품질과 유지보수 책임을 진다.

## 예시
- "로그인 실패 시 에러 메시지가 안 보인다. 재현 테스트를 먼저 작성하고, 통과하도록 고쳐 줘. `npm test`가 통과해야 끝."
- 보안 민감 코드(결제·인증)는 AI 작성 후 사람이 한 줄씩 리뷰.
