# 서버 중첩 에이전트

> MCP 서버의 도구 안에서 sampling으로 LLM을 다시 호출해, 도구 하나가 스스로 여러 단계를 추론하는 "작은 에이전트"처럼 동작하게 하는 설계다.

## 쉽게 말하면
고객이 "견적 좀 내 주세요"라고 하면 영업 담당(도구)이 혼자 끝내지 않고, 본사 분석가(LLM)에게 자료를 보내 의견을 받은 뒤 정리해 답한다. 분석가의 비용·권한은 고객(클라이언트) 쪽에서 통제한다.

## 자세히
- 명세는 sampling이 "에이전트적 동작을 구현하게 하며, LLM 호출이 **다른 MCP 서버 기능 안에 중첩**되어 일어난다"고 설명한다(2025-06-18).
- 구조: 클라이언트(호스트 앱의 LLM) → 도구 호출 → 서버 도구 실행 중 `sampling/createMessage` → 클라이언트가 자기 모델로 생성(사람 검토 포함) → 서버가 결과를 이용해 도구 응답 반환.
- 장점: 서버에 API 키·모델 계약이 필요 없다. 모델 선택은 `modelPreferences`(cost/speed/intelligence 0~1과 hints)로 추상화되어 클라이언트가 최종 결정한다.
- 위험: 요청이 연쇄되어 토큰·비용이 폭증할 수 있다. 상한(`maxTokens`), 속도 제한, 깊이 제한, 사람 승인([Sampling 사람 검토](#mcp-sampling-hitl))이 필요하다.
- 현실 주의: 클라이언트가 sampling을 지원해야 쓸 수 있다. 지원 여부는 클라이언트마다 다르므로 `sampling` capability를 확인한다.

## 그림으로 보기
```mermaid
flowchart LR
  H["호스트 LLM"] -->|도구 호출| T["서버 도구"]
  T -->|sampling 요청| C["클라이언트"]
  C --> M["클라이언트의 모델"]
  M --> C --> T --> H
```

## 예시
"코드 리뷰" 서버 도구가 diff를 읽은 뒤, sampling으로 "보안 관점 요약"과 "스타일 관점 요약"을 각각 요청해 합친 리포트를 돌려준다. 서버 코드는 모델 이름을 모른 채 `intelligencePriority: 0.8`만 지정한다.

## 헷갈리는 것과 비교
| 개념 | 차이 |
|---|---|
| 일반 도구 | 결정적 코드를 실행 |
| 중첩 에이전트 도구 | 도구 안에서 LLM을 추가 호출 |
| 멀티에이전트 | 독립 에이전트 여러 개가 협업. 여기는 한 호스트 안의 호출 연쇄 |
